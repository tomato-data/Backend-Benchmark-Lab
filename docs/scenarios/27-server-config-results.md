## Round 1: I/O-bound (1 vCPU)

### 분석

**가설 H1 기각**: gunicorn-4w가 모든 VU 레벨에서 우세.

다만, RPS 차이는 3~6% 수준으로 크지 않다. 진짜 의미 있는 차이는 **P99 레이턴시**:

- VU=200에서 uvicorn P99 = 145ms, gunicorn-4w P99 = 126ms (약 13% 차이)
- VU가 올라갈수록 격차가 벌어짐

**해석**: 순수 I/O-bound(`asyncio.sleep`)에서도 멀티프로세스가 약간 유리한 이유:

- 단일 이벤트 루프가 200개 코루틴을 스케줄링하는 오버헤드
- 멀티프로세스는 각 워커가 50개(200÷4)씩만 담당 → 코루틴 스케줄링 부하 분산
- 특히 tail latency(P99)에서 이 효과가 드러남

**실무 시사점**: I/O-bound 워크로드라도 고동시성(VU 100+) 환경에서는 멀티워커가 P99를 안정적으로 유지하는 데 도움이 된다.

### 분석

**가설 H2 채택**: CPU-bound에서 멀티프로세스가 압도적으로 우세.

#### 핵심 발견

1. **RPS: Gunicorn-2w가 Uvicorn 대비 약 1.86배** (VU=10 기준)
   - 2개 프로세스 = 2개 GIL = 2개 CPU 코어에서 병렬 연산
   - 이론상 2배에 가까운 수치

2. **Uvicorn의 이벤트 루프 블로킹 현상**
   - VU=10에서 RPS 8.53 → VU=100에서 RPS 9.31: VU를 10배 올려도 RPS가 거의 안 늘어남
   - 단일 프로세스에서 `fibonacci(32)`가 이벤트 루프를 완전히 점유
   - 한 요청이 끝나야 다음 요청 처리 → 사실상 **직렬 처리**

3. **Uvicorn VU=100에서 P99 = 60,000ms (= 60초 = 테스트 전체 시간)**
   - 이벤트 루프가 블로킹되면 뒤에 대기하는 요청들이 **테스트 종료 시점까지** 응답을 못 받음
   - 서비스 장애 수준의 레이턴시

4. **Gunicorn-4w가 2w보다 약간 낮은 RPS**
   - 2 vCPU 환경에서 4워커는 CPU보다 워커가 많음
   - 컨텍스트 스위칭 오버헤드 발생 → 문서의 예상대로
   - 단, P99는 4w가 더 낮음 (요청 분산 효과)

**실무 시사점**: CPU-bound 작업이 포함된 Python 서비스에서 Uvicorn 단독은 위험하다. 반드시 멀티프로세스 구성이 필요하며, 워커 수는 vCPU 수에 맞추는 것이 최적이다.

## Round 3: I/O-bound 저사양 (0.25 vCPU)

**가설 H3**: 저사양에서 멀티프로세스는 오히려 역효과다.

### 조건

| 변수     | 값          |
| -------- | ----------- |
| 워크로드 | `/io/sleep` |
| CPU      | 0.25 vCPU   |
| VU       | 10 → 50     |

### 결과

| Config      | VU  | Runs | RPS (avg±std)     | Latency avg | P50   | P95   | P99   | Error % |
| ----------- | --- | ---- | ----------------- | ----------- | ----- | ----- | ----- | ------- |
| uvicorn     | 10  | 3    | 93.07±0.16        | 107ms       | 107ms | 111ms | 112ms | 0%      |
| uvicorn     | 50  | 3    | 442.17±2.77       | 113ms       | 112ms | 119ms | 173ms | 0%      |
| gunicorn-2w | 10  | 3    | 94.09±0.34        | 106ms       | 105ms | 112ms | 114ms | 0%      |
| gunicorn-2w | 50  | 3    | 460.86±4.3        | 108ms       | 106ms | 112ms | 161ms | 0%      |
| gunicorn-4w | 10  | 3    | 95.6±0.6          | 104ms       | 104ms | 109ms | 110ms | 0%      |
| gunicorn-4w | 50  | 3    | 463.66±1.18       | 108ms       | 106ms | 114ms | 117ms | 0%      |

### RPS 비교

| VU  | uvicorn | gunicorn-2w         | gunicorn-4w | Winner      |
| --- | ------- | ------------------- | ----------- | ----------- |
| 10  | 93.07   | 94.09               | **95.6**    | gunicorn-4w |
| 50  | 442.17  | 460.86              | **463.66**  | gunicorn-4w |

### 분석

**가설 H3 기각**: 0.25 vCPU에서도 멀티프로세스가 역효과를 보이지 않음.

#### 핵심 발견

1. **세 구성 모두 유사한 성능**
   - uvicorn: 442.17, gunicorn-2w: 460.86, gunicorn-4w: 463.66 (차이 5% 이내)
   - I/O-bound에서는 워커 수에 관계없이 CPU 경합이 미미

2. **gunicorn-4w가 근소하게 최고 RPS**
   - 0.25 vCPU에서 4워커임에도 RPS 463.66 (최고)
   - I/O-bound에서는 워커가 대부분 I/O 대기 상태이므로 CPU 경합이 미미
   - 이벤트 루프 코루틴 분산 효과가 여전히 작동

3. **Round 1(1 vCPU)과 비교**
   - uvicorn VU=50: 1 vCPU → 447 RPS, 0.25 vCPU → 442 RPS (거의 동일!)
   - I/O-bound에서는 CPU가 0.25여도 충분 → 진짜 병목은 I/O 대기이므로 CPU를 거의 안 씀

**실무 시사점**: I/O-bound 워크로드에서는 Fargate 0.25 vCPU로도 충분한 처리량을 낼 수 있다. 워커 수(2w, 4w)에 관계없이 성능이 안정적이므로, 저사양 I/O-bound 서비스에서는 서버 구성 선택이 자유롭다.

## Round 4: CPU-bound 저사양 (0.25 vCPU)

**가설 H3 검증 (CPU)**

### 조건

| 변수     | 값                    |
| -------- | --------------------- |
| 워크로드 | `/cpu/fibonacci?n=32` |
| CPU      | 0.25 vCPU             |
| VU       | 10                    |

### 결과

| Config      | VU  | Runs | RPS (avg±std) | Latency avg | P50      | P95          | P99          | Error % |
| ----------- | --- | ---- | ------------- | ----------- | -------- | ------------ | ------------ | ------- |
| uvicorn     | 10  | 3    | 0.92±0.05     | 10,460ms    | 10,667ms | 17,883ms     | 27,727ms     | 0%      |
| gunicorn-4w | 10  | 3    | 0.27±0.01     | 30,857ms    | 18,905ms | **60,001ms** | **60,001ms** | 0%      |

### RPS 비교

| VU  | uvicorn  | gunicorn-4w | Winner  | 배율     |
| --- | -------- | ----------- | ------- | -------- |
| 10  | **0.92** | 0.27        | uvicorn | **3.4x** |

### Round 2 (2 vCPU) 대비 비교

| Config      | 2 vCPU (R2) | 0.25 vCPU (R4) | 하락율   |
| ----------- | ----------- | -------------- | -------- |
| uvicorn     | 8.53 RPS    | 0.92 RPS       | **-89%** |
| gunicorn-4w | 15.24 RPS   | 0.27 RPS       | **-98%** |

### 분석

**가설 H3 채택 (CPU-bound)**: 저사양 + CPU-bound + 멀티프로세스 = 최악의 조합.

#### 핵심 발견

1. **Gunicorn-4w RPS = 0.27** (60초에 약 16개 요청만 처리)
   - 0.25 vCPU를 4개 워커가 나눠 씀 → 워커당 0.0625 vCPU
   - fibonacci(32)는 순수 CPU 연산 → CPU가 없으면 답이 없음
   - P95/P99 = 60,001ms → 대부분의 요청이 **테스트 종료까지 응답을 못 받음**

2. **Uvicorn이 3.4배 우세**
   - 단일 프로세스가 0.25 vCPU를 독점 → 프로세스 스케줄링 오버헤드 없음
   - 여전히 느리지만(0.92 RPS) gunicorn-4w보다는 훨씬 나음

3. **CPU 자원 대비 성능 붕괴**
   - uvicorn: 2 vCPU → 0.25 vCPU = CPU 1/8로 줄었는데, RPS는 8.53 → 0.92 = 1/9로 감소 (거의 비례)
   - gunicorn-4w: 15.24 → 0.27 = **1/56로 감소** (비례 이상의 붕괴)
   - 멀티프로세스의 스케줄링 오버헤드가 저사양에서 **기하급수적으로** 증가

**실무 시사점**: Fargate 0.25 vCPU에서 CPU-bound 작업을 돌리면서 Gunicorn 멀티워커를 쓰는 것은 돈 낭비 + 서비스 장애 수준이다. 저사양에서 CPU-bound가 불가피하면 Uvicorn 단독이 차선.

## Round 5: Mixed (1+2 vCPU)

### 조건

| 변수     | 값                                    |
| -------- | ------------------------------------- |

| uvicorn     | 1   | 50  | 3    | 203.7±1.37     | 245ms       | 133ms | 636ms   | 976ms    | 0%      |
| uvicorn     | 2   | 50  | 3    | 205.12±5.12    | 243ms       | 142ms | 624ms   | 924ms    | 0%      |

| gunicorn-2w | 2   | 50  | 3    | 351.82±12.8    | 142ms       | 137ms | 190ms   | 234ms    | 0%      |
| gunicorn-4w | 1   | 50  | 3    | 100.48±0.96    | 496ms       | 443ms | 1,002ms | 1,267ms  | 0%      |
| gunicorn-4w | 2   | 50  | 3    | 297.39±3.4     | 168ms       | 163ms | 320ms   | 431ms    | 0%      |

### RPS 비교

| CPU    | uvicorn    | gunicorn-2w | gunicorn-4w | Winner          |
| ------ | ---------- | ----------- | ----------- | --------------- |
| 1 vCPU | **203.7**  | 191.25      | 100.48      | **uvicorn**     |
| 2 vCPU | 205.12     | **351.82**  | 297.39      | **gunicorn-2w** |

### P99 Latency 비교

| CPU    | uvicorn | gunicorn-2w | gunicorn-4w |
| ------ | ------- | ----------- | ----------- |
| 1 vCPU | 976ms   | **418ms**   | 1,267ms     |
| 2 vCPU | 924ms   | **234ms**   | 431ms       |

### 분석

Mixed 워크로드는 예측이 가장 어려웠고, 실제로 가장 복잡한 결과가 나왔다.

#### 핵심 발견

1. **1 vCPU: Uvicorn 단독이 최고 RPS**
   - Uvicorn 204 RPS > Gunicorn-2w 191 RPS > Gunicorn-4w 100 RPS
   - 1 vCPU에서 멀티워커는 CPU 가공 단계에서 컨텍스트 스위칭 오버헤드 발생
   - gunicorn-4w는 RPS가 절반으로 하락

2. **2 vCPU: Gunicorn-2w가 압도적**
   - Gunicorn-2w 352 RPS > Gunicorn-4w 297 RPS > Uvicorn 205 RPS
   - 2워커가 DB 조회(I/O)와 집계(CPU)를 각각 분담 → **1.7배 향상**
   - **워커 수 = vCPU 수가 최적**이라는 Round 2의 결론 재확인

3. **Uvicorn은 CPU를 늘려도 성능 동일** (204 → 205 RPS)
   - 단일 프로세스는 어차피 1개 코어만 사용 → 2 vCPU를 줘도 의미 없음
   - CPU를 추가 투자해도 멀티프로세스가 아니면 활용 불가

4. **P99에서 Gunicorn-2w가 모든 CPU 레벨에서 최고**
   - 1 vCPU: 418ms (uvicorn 976ms의 절반 이하)
   - 2 vCPU: 234ms (가장 낮은 tail latency)
   - 멀티워커가 요청을 분산 → 특정 요청이 CPU 가공에 막히는 현상 완화

**실무 시사점**:

- **1 vCPU 이하**: Uvicorn 단독이 RPS 기준 안전한 선택. 단, P99는 gunicorn-2w가 더 낮음
- **2+ vCPU**: Gunicorn + (vCPU 수 = 워커 수) 구성이 RPS, P99 모두 최적
- vCPU보다 워커가 많으면 Mixed 워크로드에서 성능 하락 (4w@1vCPU: RPS 절반)

| H2: CPU-bound에서 멀티프로세스 우세         | **채택**        | Gunicorn-2w가 1.86배 (GIL 우회 효과)                               |
| H3: 저사양에서 멀티프로세스 역효과          | **조건부 채택** | I/O-bound → 역효과 없음 (모든 구성 안정), CPU-bound → 극심한 역효과 (98% 성능 하락) |

### 서버 구성 가이드

| 워크로드 유형                     | 1 vCPU 이하     | 2+ vCPU                                 |
| --------------------------------- | --------------- | --------------------------------------- |
| **I/O-bound** (API 호출, DB 쿼리) | Uvicorn 단독 ✅ | Gunicorn + N워커 (약간 이득)            |
| **CPU-bound** (연산, 해싱)        | Uvicorn 단독 ✅ | **Gunicorn + N워커 필수** (N = vCPU 수) |
| **Mixed** (현실적 서비스)         | Uvicorn 단독 ✅ | **Gunicorn + N워커 필수** (N = vCPU 수) |

> **핵심 원칙**: 워커 수는 절대 vCPU 수를 초과하지 마라. 초과하면 I/O-bound에서도 불안정, CPU-bound에서는 서비스 장애 수준.

### Fargate 배포 시 권장 구성

| Fargate 스펙 | 권장 구성                        | 이유                                |
| ------------ | -------------------------------- | ----------------------------------- |
| 0.25 vCPU    | Uvicorn 단독                     | 멀티워커 오버헤드가 성능을 잡아먹음 |
| 0.5 vCPU     | Uvicorn 단독                     | 동일                                |
| 1 vCPU       | Uvicorn 단독 또는 Gunicorn 1워커 | Mixed에서 Uvicorn이 근소 우세       |
| 2 vCPU       | Gunicorn + 2워커                 | CPU-bound/Mixed에서 확실한 이득     |
| 4 vCPU       | Gunicorn + 4워커                 | 병렬 처리 극대화                    |
